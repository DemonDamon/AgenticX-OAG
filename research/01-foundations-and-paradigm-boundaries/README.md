# 01 · 概念基础与范式边界



本方向回答：**当技术团队说“本体”时，实际在讨论形式语义、知识图谱 Schema、Palantir 操作型对象模型，还是 Agent 运行时约束？** 它为全仓库提供术语、概念地图和归档边界；不承担任何特定平台、检索或规则实现研究。



| 问题 | 预期交付 |

|---|---|

| 哲学本体论、信息科学 Ontology 与工程数据模型的连续性和断裂是什么？ | 概念谱系与术语表 |

| 语义本体、KG Schema、Palantir Ontology、Agent Ontology 如何在数据模型、推理与操作语义上区分？ | 四象对照矩阵 |

| OWL/RDF/SHACL、标签属性图、Object/Action、Constraint/Harness 分别适合什么问题？ | 选型前置检查清单 |

| 哪些表述会造成“万物皆本体”的混淆？ | 反模式与边界案例 |



## 初始资料



本方向以 W3C 标准、公开论文、厂商公开架构资料和项目实验为可引用依据。受限参考资料不在仓库记录可识别元数据、章节页码、连续摘录或全文转写；其启发只能作为待验证问题，不能单独支撑通用结论。



| 范式 | 主问题 | 代表形式 | 主操作 |

|---|---|---|---|

| 语义本体 | 如何用形式语义描述并推理领域知识？ | RDF / OWL / SHACL | 一致性检查、分类、推理 |

| 知识图谱 Schema | 如何高效组织、关联与查询业务数据？ | 标签属性图、图数据库 Schema | 遍历、聚合、路径查询 |

| Palantir 本体 | 如何把对象、逻辑、动作与治理连接为决策闭环？ | Object / Link / Action / Function | 受控读写与决策 |

| Agent 本体 | 如何约束 Agent 的能力、权限和行为边界？ | Tool Contract / Policy / Harness | 校验、拦截、审批、审计 |
